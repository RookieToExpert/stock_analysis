# 历史时点数据可行性

检查日期：2026-11-05。对应 issue #3。

## 结论

| 数据 | 结果 | 依据 |
|---|---|---|
| 历史 ST 状态 | **可用** | Baostock 日线 `isST`：12 个 ST 公告样本全部符合，11 只在公告后第一个交易日翻转，1 只当时已是 ST |
| 财报原始版本 | **部分可用** | Baostock 3 家已知调整公司的净利润都等于当期公告原值，公告日也一致 |
| 退市股票 | **抽查可用** | 已退市的 600087、000004、000018 能查到基础信息或财务数据 |
| 东方财富财报 | **不能回测** | 4 张表都返回调整后的值，更新日也不能识别修订 |

## Baostock 字段覆盖

| 模型需要 | Baostock | 状态 |
|---|---|---|
| 公告日 | `pubDate` | 有 |
| 合并净利润、毛利率、ROE | `netProfit`、`gpMargin`、`roeAvg` | 有 |
| 经营现金流 | `CFOToNP` × `netProfit` | 可推算 |
| 资产负债率 | `liabilityToAsset` | 有 |
| 现金分红和除息日 | `dividCashPsBeforeTax`、`dividOperateDate` | 有 |
| 每日 ST、当日股票列表 | `isST`、`query_all_stock` | 有 |
| 扣非净利润 | 未找到 | 缺 |
| 资本开支、自由现金流 | 未找到 | 缺 |
| 商誉、现金、有息负债金额 | 未找到 | 缺 |

现有模型不能原样回测。使用 Baostock 时，需要先写新的策略版本，并在看结果前冻结替代规则。

验证样本较小：财报只核对了 3 家公司，ST 只核对了 12 个公告。全量使用前还要继续抽查。

- 下载和解析预计 1～2 天。
- #6 的核对可以用快照值定位，全量提取没有已知答案，错误率未知。

## 下载中断

2026-11-05 全量下载以 3 个进程运行，完成 428 / 5457 只后，接口返回：

```text
10001011 黑名单用户，请与管理员联系
```

脚本在每个分片连续失败 10 只后自动停止。已完成的数据不足以运行回测。不要通过换代理、换 IP 或换账号绕过限制。

恢复前需要确认封禁范围和允许频率。

## 恢复下载的限制

11-05 下载用 3 个进程并发，当天约 6.2 万次请求，同时不符合第三方引用的官方规则：单公网 IP 不能并发、每日不超过 5 万次。官网原文未读到。当时为直连；客户端使用裸 TCP，不读 HTTP 代理变量。

11-06 06:59 探测通过（登录、查询 `sh.600000`、登出，共 3 条消息）。此后 `model/pit_fetch.py` 由 `model/pit_guard.py` 限制：

- 单进程文件锁，`--shard` 已移除。
- 请求至少隔 1 秒，北京时间每天最多 4 万次；计数写在 `data/pit_state/state.json`。
- 收到 `10001011` 立即退出，写 `data/pit_state/blocked.json`；标记存在时不发请求。
- 跳过上市前两年以前、退市后、法定披露截止日未到的报告期。上市前留两年，是因为浙江新能 2021-05 上市，2020 年报 2021-04 已公告。
- 一次请求从发送到收完最多 60 秒。超时、对方关闭连接、连接被重置或没有响应，都算网络错误：丢弃当前连接，等 5 分钟，只重新登录一次。
- 重新登录失败，或之后还没存下一只股票又出现网络错误，进程停止，等人工决定。存下一只股票后，这个判断才清零。启动时的登录和 `--probe` 出现网络错误时直接退出，不重连。
- 服务器返回错误码时仍是等 5 秒后重新登录，连续失败 10 只停止。

已下载 428 只按新规则只少 479 行，公告日全部晚于退市日，回测用不到。样本中 2012 年后上市的只有 3 只，上市前余量要在下载新股后复核。

超时规则来自 11-06 的试跑：21:15 之后没有新请求，日志也没有报错，进程一直停到 23:55 被时间上限结束。当时没有抓进程堆栈，无法确定是一直等响应，还是下面第二种空转。

客户端 0.9.4 的 `send_msg` 有三个问题，都由 `pit_guard.py` 的 `Deadline` 和 `Guard.call` 处理：

- 不设超时，对方不回时一直等。
- 对方正常关闭连接时 `recv` 返回空，接收循环不退出，socket 超时也拦不住。
- 吞掉所有异常后返回 None；翻页时 None 被当成数据读完，错误码仍为成功。现在这种情况抛错，这只股票不存盘。已下载的数据是否受过影响未检查；日线不足 1 万行，不触发翻页。

验证：`cd model && python3 -m unittest` 共 115 个通过；另用真实客户端连本机假服务器，覆盖不回、关闭连接、重置、持续滴数据四种故障，以及重新登录成功和失败两种结果，共 8 个场景，请求数和连接数符合预期。这个脚本不在仓库里。
